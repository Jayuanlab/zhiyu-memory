# 单场景实施与验证

## 实施前确定接缝

沿项目已有模块接口实现，不预设 Node.js、数据库类型或消息中间件。选择一个场景，把来源读取、知识提炼、记忆传输与业务入口各自的职责放到可单独验证的位置。小项目无需为了套模板增加多层抽象；已有事件／工单／文档接口应优先复用。

根据用户本次授权继续实施。已明确要求改造时，不因内部阶段切换重复索要批准；只有评估或方案请求时，保留业务代码与运行数据不变。任何缺失配置都要说明影响，但先完成不依赖它的本地工作。

## 来源 Adapter

来源至少应能做到：

- 从稳定 ID 在当前身份下重新读取指定业务来源，检查项目及来源访问权限。
- 取得真实原文、版本、时间和可用期限；内容变化必须反映到来源版本。
- 让知识引用的版本、原文摘录和范围可核验。使用 Unicode code points 计数，保留原始换行。
- 对删除、来源不可用、权限撤销和版本不一致给出明确结果，阻断不再有效的知识。

如果要脱敏或转换正文，保存并重读这个有明确权限和版本的派生来源，记录与原来源的关系。不能引用原文版本，却让摘录来自另一份改写文本；不能用文档内任意一句话作为脱敏后正文的完整证据。

来源权限检查应在读取／使用时仍然有效。通过内存布尔值、测试假身份或一次导入时的判断不能替代实际服务授权与来源最终核验。

## 采集与一致性

优先利用已有业务完成事件或后台任务。需要可靠交付时，把 outbox 记录写入**业务提交所在的同一个事务**，由 worker 在提交后发送；不要把远程 HTTP 调用加入业务事务，也不要在提交后才创建唯一的可靠投递记录。

明确现有事件是至少一次、至多一次还是只在内存中通知。事件机制不可靠时，提出并在授权范围内实现持久化或对账回补，不因为监听回调能触发就声称可靠采集完成。

用业务来源 ID、真实版本与操作类型生成稳定事件／命令标识；同一命令保留原始正文及回执。相同 ID 不允许改正文。至少一次投递由幂等处理，而不是声称端到端恰好一次。

普通提案、审核等写入结果未知时，按原命令查回执或同 ID 同正文恢复。受控 dispatch 的结果未知时，按原使用凭证查状态，不能把它交给通用自动重试队列。身份库、业务库与远程记忆库之间没有自动分布式事务。

业务提交不依赖记忆服务在线；worker 错误应可观察、保留待恢复工作。记录字段数量和任务所需内容，避免持久化令牌和无关客户原文。

## 候选与审核

只有满足来源和场景准入条件的资料才生成知识候选。例如，案例必须已经完成复盘，单纯关闭工单并不必然意味着结论有效。

提炼结论时保留适用条件、反例和依据。候选提交成功不等于审核生效。普通采集身份与实际审核身份分别配置，沿用项目既定流程；没有业务确认或审核权限时，保留候选及其状态。

默认研发策略接受的分类不代表目标项目策略。需要新的案例、规范或偏好类型时实现或配置相应业务策略，不用随意增加 `team-rule` 标签绕过分类。

来源变更、复盘纠正、撤权或到期时，旧知识应立即不可用；获取新来源后按修订和审核流程更新。来源已变更而旧知识查询仍成功，不能只通过“以后定时同步”解释为已完成正确接入。

## 读取入口

将检索放在真正需要知识的任务入口，携带问题与必要上下文，限制到本项目和适当分类。读取结果保留依据、适用条件、反例、截断与遗漏信息。退款进度、库存等事实继续通过原业务查询接口获取。

成功空召回与服务不可用应明确区分。没有记忆可用时执行项目约定的降级方式，不能用假定规则补出成功答案。受控模型交付只有在项目确实安装对应消费者时才实施。

## 验收证据

使用项目测试框架，从外部可观察行为验证改造。按所选场景覆盖相关项：

| 情形 | 观察目标 |
| --- | --- |
| 目标任务的改写问题 | 能取得正确知识及来源；不能只用原文精确匹配证明语义召回 |
| 候选尚未审核 | 不作为有效长期知识召回 |
| 来源更新、撤权或过期 | 旧知识被阻断，新版本按实际流程生效 |
| 不同 namespace／来源权限 | 无权读取、写入或使用其他范围的资料 |
| 同一事件或命令重复 | 无重复知识写入，命令正文变化可识别 |
| 投递超时、服务离线、进程恢复 | 主业务提交正常，任务状态可恢复，结果未知按原回执核对 |
| 当前业务状态变化 | 回答使用实时接口的新结果，不能沿用案例中的旧状态 |
| 不符合入选条件的事件 | 不生成知识候选，能说明筛选原因 |

先跑相关业务基线，再运行新场景测试。不要仅测试函数是否被调用，或断言生成文档里含有某个词就声称业务接入正确。

没有实际目标服务配置时，传输替身可以验证载荷、幂等、失败恢复与业务隔离；不能据此报告真实身份校验、真实审核、真实向量检索或服务联调已通过。提供已运行命令、结果和未覆盖项。

回退应能停止该场景的采集与读取接线，保留必要回执和历史，恢复原任务路径。具体迁移与回滚方式按项目既有机制实现，不自动删除历史或重置业务库。
