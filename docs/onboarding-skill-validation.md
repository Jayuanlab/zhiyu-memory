## 实施测试观察

实际重新运行冻结后实施副本的 `npm test`，18 项全部通过，涵盖：

- 已关闭且完成复盘才生成候选；普通关闭事件和未复盘工单不生效。
- 候选在独立审核前不可召回，普通采集身份不能自行审核。
- 来源版本、摘录、中文／emoji 和脱敏字段可核验；旧事件不冒充当前版本。
- 来源纠正、删除、撤权、到期与最终使用前撤权阻断旧经验。
- 本地测试身份的 namespace、来源授权、提案、回执与检索隔离。
- 重复事件幂等、响应丢失后重启核对原回执、同 ID 不同正文拒绝。
- 传输离线时业务提交、实时回调和原通知消费者继续正常运行；任务可恢复。
- 客服回答使用实时退款结果，历史经验保留适用范围、反例与来源；关闭采集和读取接线可回退。
- 客服入口强制宿主提供当前退款访问授权，初次查询和召回后的实时查询均检查；伪造或撤销退款授权时拒绝回答。

## 验证边界

本轮证明了三种任务范围的实际产出，以及一个业务场景的离线适配行为。它不证明所有传统项目均可自动接通，也不证明生产鉴权、实际服务审核、真实 embedding 或业务收益。

目标项目真正联调仍需专属 namespace／身份、业务来源与权限适配、相应分类策略和实际服务调用工具。样例中的本地参考传输不兼容替代真实标准 K 协议；生产接线必须按目标 capabilities 与宿主契约实现，不可只换 URL。原业务 HTTP 在样例中仍未接入生产身份中间件，客服入口保留为宿主调用函数。
