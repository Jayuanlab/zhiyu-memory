# 项目记忆接入 Skill

`zhiyu-memory-onboarding` 面向传统或已有业务项目，帮助智能体确定哪些知识值得接入、来源和权限如何适配，以及如何改造并验证一个实际场景。它与日常读写记忆的 `zhiyu-memory` 分开。

## 第一版能力

| 模式 | 交付 |
| --- | --- |
| 项目评估 | 有代码／文档证据的业务信息地图、记忆机会、实时查询与待确认信息，保留覆盖限制 |
| 改造方案 | 每个选中场景的来源、权限、写入／读取时机、审核、更新失效、可靠投递、具体改造点和验收任务 |
| 单场景实施 | 在项目原有语言与框架中实现必要的 Adapter 和接线，运行相关测试，明确剩余环境与服务联调工作 |

Skill 是可复用的智能体工作规程，不是常驻采集服务或统一代码生成器。它不假定所有业务模块都应向量化；实时订单、库存、余额等数据继续从原业务接口查询。没有凭证和目标服务配置时可以完成离线适配验证，但应明确报告尚未真实联调。

## 安装与调用

将仓库 `skills/zhiyu-memory-onboarding` 整个目录安装到宿主技能目录。默认本机目录为 `~/.codex/skills/zhiyu-memory-onboarding`；设置了 `CODEX_HOME` 时使用该目录下的 `skills/zhiyu-memory-onboarding`。Skill 内含所需参考和方案模板，不依赖本仓库绝对路径。

在目标项目的对话里按需要使用：

```text
使用 $zhiyu-memory-onboarding 评估当前项目。
目标是让客服智能体处理退款异常时能参考已确认的历史经验。
先输出有依据的接入机会、实时查询需求和缺项，保持业务代码不变。
```

```text
使用 $zhiyu-memory-onboarding，为退款异常案例设计接入方案。
明确来源版本、业务权限、写入与读取触发、审核和旧知识失效，
把任务定位到实际文件或事件，并给出验收方法。
```

```text
使用 $zhiyu-memory-onboarding，实施退款复盘案例这一个场景。
复用现有事件机制，保留当前退款状态的实时查询，
完成适配和相关测试。缺少真实服务配置时先完成可验证的本地工作，
明确报告剩余接线项与实际完成级别。
```

调用时提供当前项目位置、目标使用者和任务，以及已有的记忆服务配置位置；不在对话中粘贴令牌。其他项目使用自己的身份和 namespace，不直接复用本仓库固定的 `memory-lab` 包装器。

## 验证范围

Skill 包结构通过创建工具的格式校验。行为验证使用隔离的传统退款／工单样例，分别检查只评估、只规划和单场景实施的实际产物与代码行为；模拟传输通过只证明本地适配契约，不证明真实服务、审核或向量检索通过。

服务本身的真实本地 embedding 验收与本 Skill 的接入行为验收是两组不同检查，不能互相替代。此版本的实际测试记录见 [验证报告](onboarding-skill-validation.md)。
